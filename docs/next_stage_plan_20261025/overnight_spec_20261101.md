## 5. L1：增强设计和必须通过的检查

### 固定配方

两组共享同一G0、初始权重生成、图像顺序、标准化、batch、loss、优化器和评价；唯一因素为联合增强开关。增强按`seed/epoch/image_index`生成独立随机数，不消耗模型初始化、dropout或sampler的全局RNG。

增强顺序固定为：

```text
原始有效图像和像素坐标
  → D4几何变换，同步坐标
  → 有效图像逐图z-score
  → 以0.8概率施加强度变换 Z'=aZ+b，a~U[0.8,1.2]，b~U[-0.2,0.2]
  → 右/下补零至512，生成有效区域mask
  → 从变换后的原始坐标重新编码网格4目标
```

D4为`np.rot90(k)`的k∈{0,1,2,3}均匀取值，再独立以0.5概率水平翻转，共8种等概率变换。无任意角旋转、resize、crop、插值或额外噪声；强度变化后不再次标准化或裁剪z-score。

**原因**：当前`normalize_image`是逐图减均值/除标准差，若把正线性强度变化放在它之前，变化会被抵消。必须直接测试最终网络输入确实改变，不能只测试增强函数被调用。

### 坐标、数值和mask

- 以整数索引为像素中心：水平翻转`x'=W-1-x`，逆时针90°旋转`(y',x')=(W-1-x,y)`；按实际输出宽高更新，不能旋转旧的已编码offset网格。
- 本次只读检查发现3个训练点略高于末像素中心，最大约一个float32步长（约3.1e-5px）。计算几何变换使用float64；仅当变换结果越出合法坐标域不超过**1e-4px**时，允许对增强副本作边界数值吸附并逐次记录原值、变换、修正量。大于容差立即报错，不丢点、不静默clip，不修改原标签。
- 原始开发验证标签不作吸附；几何往返与距离检查容差为1e-4px，并单列边界吸附样本，不能要求这些点逐bit可逆。
- 256图先在256有效视野内变换和标准化，再右/下补零；补齐区域始终为0并由mask排除loss/评价。强度偏移不得污染补齐区域。
- 网格碰撞采用既有冻结规则，保存变换前后碰撞/编码点数。D4可能改变单槽网格内的碰撞分配；不得丢弃原始参考点或将被编码点数冒称全部真值。静态审计先冻结每图每种D4的碰撞计数，训练时必须与之匹配；不按碰撞数挑变换或删图，不通过修改验证真值解决。

### 验收项目

全部198张开发图做几何只读检查，正式随机增强仍只作用于训练集；每图覆盖8种D4。检查图像/坐标变换一致、点数不变、合法范围、几何往返、无插值、有限数值、mask面积与补齐零值、目标编码重建、验证/推理恒等路径。

另做固定a/b的最终输入检查，证明有效像素均值/尺度确有改变；关闭增强必须复现原预处理。跨seed/epoch增强不同，同键重载相同。真实256/512图各做CPU前向/反向，检查有效loss及有限梯度。任一失败则Gate-L1失败，不进入正式训练。

## 7. L3：LoG/DoG开发对照

实现为本项目可复核的尺度空间LoG/DoG加公共候选NMS适配器，明确与库函数的默认完整流程不同，不冒称某论文的官方复现。坐标为整数像素峰位置，无新增亚像素精修。

输入采用原始有效视野的逐图1–99.8百分位缩放至[0,1]，常量图输出0；Gaussian边界`reflect`。LoG响应为`-sigma² * gaussian_laplace(I,sigma)`，DoG响应为`(G_sigma(I)-G_(r*sigma)(I))/(r-1)`；对配置内尺度取最大正响应，保留3×3空间局部极大，再按响应降序、坐标字典序打破并列，做欧氏距离NMS。无边界带排除；所有平局/零响应行为写入实现与测试。

| 方法 | 参数网格 | 数量上限 |
|---|---|---:|
| LoG | min_sigma={0.6,1.0}；max_sigma={2,3,4}；几何等比尺度数={4,8}；NMS距离={1,2}px | 24配置 |
| DoG | min_sigma={0.6,1.0}；max_sigma={2,3,4}；ratio={1.4,1.8}；NMS距离={1,2}px | 24配置 |

DoG的较小sigma按min_sigma×ratio^k生成至不超过max_sigma，对应较大sigma=ratio×较小sigma，实际使用尺度写入账本。LoG使用`geomspace(min,max,num_scales)`。

阈值按每配置**训练图候选正响应**的合并分位点生成，不读取训练标签或验证标签确定网格：29个分位数为`linspace(0,0.9,19)`与`[0.925,0.95,0.975,0.99,0.995,0.9975,0.999,0.9995,0.9999,1]`，再加全保留/全不保留边界，去重后最多31个。不得对整幅稀疏响应像素作均匀分位导致有效高分阈值缺失；阈值生成规则在读取验证分数前锁定。

验证集仅在固定网格内选配置/阈值：micro-F1、Precision、较早config_id、较高阈值依次打破并列。全量每方法最多744组，两方法共1488组；完整记录实际去重数。经典方法不是3次训练重复，不生成伪seed SD，也不混入三个训练种子的显著性检验。

单元检查至少覆盖亮点高斯合成图、空/常量图、边界峰、近邻抑制和坐标方向；然后真实256/512图预检。产物包含全部配置、训练阈值来源、候选、22图匹配、主选指标和不利结果。部分扫描只报告partial；不因低分换sigma区间。

## 8. L4与Night-G：两组G0的正式协议

| 项目 | 固定值 |
|---|---|
| 配置 | `G0_ref_cuda`、`G0_aug_cuda`，唯一因素为第5节增强开关 |
| 数据 | 同176训练/22验证；原始有效视野，不crop |

| 顺序 | ref42→aug42→ref43→aug43→ref44→aug44；不按seed42成绩删队列 |
| 预算 | 6次×100轮=600轮；batch8、每轮22更新、每次2200更新，共13200更新 |
| 训练 | Adam，lr0.001，weight_decay0，固定lr、无scheduler，dropout0.3；Dice+2RMSE |
| 数值/设备 | 同一CUDA GPU，float32，AMP/TF32关闭，NCHW tensor采用channels_last内存格式；禁止静默回退CPU/XPU或自动改batch |
| 采样 | 每轮无放回遍历176张；同seed两组的100轮sampler顺序哈希一致 |
| 评价 | eval模式完整22图；几何/强度增强均关闭；原始372参考点、3px公共匹配 |
| 主选 | 5..100每5轮真实快照，共20；原THRESHOLDS_V3共31；按F1→P→更早epoch→更高阈值 |
| 次级 | 同20快照中native验证loss最低，再按同阈值网格；不据结果交换主次 |
| 停止 | 不early-stop，不增加搜索；异常先保留现场并按第10节处理 |

必须验证两个组dropout、初始化和sampler的RNG不被增强消耗改变。不得保存历史best替代当轮快照，导出模型必须绑定已选阈值。快照、候选、恢复点、训练记录分别保存，且恢复点每轮落盘。

## 9. 评价与结论约束

Night-G主对比为`G0_aug_cuda - G0_ref_cuda`的三种子micro-F1均值差；同时报告每个seed、P/R、FP/FN、弱点Recall（冻结96点）、macro-F1、计数MAE、TP及共同真值定位误差、尺寸分层和训练资源。

旧R0/G0、Spotiflow列为带配方/设备/预训练说明的背景参考。增强组合的结果不能拆成“某一种增强有效”，也不能写成架构改进。若补精确seed检验，单个主要对比为探索性双侧符号翻转；n=3精确p下限0.25。图像bootstrap只能标条件于已选模型的内部诊断区间，不以此覆盖来源重叠和选模偏差。没有显著性依据就标ns，不追加种子追星号。

Night-L只汇报传统方法开发结果和工程完成度；G0六次未运行时不生成新G0性能或把smoke权重当作正式模型。

## 10. 状态、异常处理与可恢复性

运行时建立真实PID、源代码哈希、配置哈希、输入哈希、环境、状态和追加事件日志。状态至少含`pending/running/completed/failed/deferred`；human_review和cuda_verification分开记录。每轮/每阶段更新机器状态，长任务至少每分钟心跳；开始/结束时间用含时区偏移的ISO时间，耗时用单调时钟。

| 异常 | 必须行为 |
|---|---|
| 输入/历史哈希变化、读到测试key | 停止全部依赖任务，保存差异，不更新旧锁 |
| 坐标超1e-4容差、点数减少、mask/目标错位、NaN/Inf | 停止相关实现；修复后重跑相关预检，不继续正式任务 |
| 旧审查缓存命中、Spotiflow回退Z1 | 使用新的版本目录和显式模型路径；旧材料不覆盖 |
| CPU过慢、磁盘不足、窗口不足 | 保存完整partial状态与未完成列表，停止重任务；不静默缩小搜索/删快照 |
| CUDA OOM、设备缺失、AMP/batch被改变 | 正式任务失败并保留；不自动改配方，不伪装等条件续训 |
| 基础设施中断 | 先核查配置/源码/数据与旧进程，使用完整epoch恢复点续训；完整任务可按哈希跳过 |
| 快照已写但该轮恢复点未写 | 保留两者及日志，审计一致边界；不直接删除快照强行续训 |
| Git冲突/主工作区出现不相关改动 | 不覆盖用户改动，隔离相关任务；数据分析可在独立输出继续 |

可自行修复范围为本SPEC内新适配器、增强、运行器和报告中的工程错误，必须记录原因、改动与验证；修复若改变已冻结语义/输入/训练配方，应建立新版本并将受影响正式任务判为不可比较，不静默续跑。
