# Scope 00：评估协议、数据质量与比较接口

状态：计划。优先级：最高；任何完整搜索前完成。修订后执行阶段P0。

## 问题与范围

先确定后续实验究竟检验什么。220对继续合并使用现有176/22/22清单，不按新旧重划，不因测试分数重新随机选测试集。现有22张测试图称为**已观察的内部基准**；改名字或重新分配不会使它变成独立盲测。

冻结原始440个输入哈希、NPZ、坐标单位与顺序`(y,x)`、原始尺寸、来源元数据和排除清单。256图像先在有效像素上标准化，再右/下补零到512，坐标不变；原始真值保留，网格碰撞不能从评估真值中删除。若发现同一生物样本、多帧或序列相关性，记录真实group_id，并为后续分组敏感性分析另建版本，不能悄悄改现有清单。

先按现有原主干与固定T_ref建立可信参考，完成v2校准及基线接口预检；完全一致的旧权重可复用。这一步不要求把DeepBlink充分调到最优。随后进入Scope 08的问题与创新性关口，再开展核心结构与训练优化。

开发标注审计建议先抽取约20%的198张开发图，由不知道模型身份的复核者检查单位、弱点、重叠点和背景纹理。原始标注不覆盖；必要修订另存版本、变更理由和不确定区域。采用新版标注后，所有比较方法在同版真值下重新评估。测试标签复核应有独立于方法表现的标准，不能只删除本方法误检多的图像或点。

## 统一评价协议v2

| 项目 | 计划规则 |
|---|---|
| 主终点 | 原始有效视野内，3像素半径一对一坐标匹配的micro-F1；主表为三个种子各自F1的均值±样本SD |
| 支持指标 | P/R、TP/FP/FN、macro-F1、逐图点数MAE；定位误差仅对TP并注明目标集合不同 |
| 阈值 | 每个方法仅在验证集选全局阈值，最大化micro-F1；并列时优先Precision更高，再选择更保守的阈值 |
| 候选阈值 | 各方法最多31个有意义候选，含“全保留/全不保留”边界；概率分数用预定线性网格，非概率响应用覆盖高分尾部的分位点。生成规则在开发阶段锁定，重复值去重；不能对高度稀疏的密集网格分数直接取均匀分位而漏掉有效高分区 |
| 其他参数 | 点尺度、峰值抑制距离等属于调参配置，计入搜索预算，不能逐测试图手调 |
| 匹配 | 审计并复用共同坐标匹配实现；所有方法一致处理边界、重复点和空预测 |
| 归一化 | 模块消融用同一512预处理；外部方法可用官方合理预处理，记录差异，保持相同原始像素信息、真实视野与坐标尺度 |
| 测试调用 | 方法、轮次、阈值和后处理锁定后统一评估，不按测试选择种子、结构或匹配半径 |

内部同架构模型按最低验证训练目标损失选轮次；外部方法按预先登记的官方验证准则选轮次，给出相同或合理记录的评估机会。各方法候选配置之间以验证点F1比较，绝不把不同损失函数的数值大小直接用于跨方法评优。最终主表报告全部三个种子；若需要单个交付模型，按验证点F1选择代表种子，并单独报告该选择规则。

阈值规则故意与前轮不同：前轮有“Precision不低于p=0.5参考”的限制，但传统方法没有统一的p=0.5语义。v2采用方法无关的验证集最大F1规则。旧0.7716成绩属于旧协议；可复用完全相同训练条件下的权重，但必须按v2重新校准和评估，不能把单独校准收益算作架构提升。

AP只有在坐标匹配、候选生成和评分排序都统一核查后才作为次要指标；不能把网格分类AP或网格F1混作点检测性能。计划报告1、2、3像素匹配半径的敏感性，但3像素始终是主终点，不选最有利半径写主结论。部分旧图没有可靠物理标定，不能把默认1.0解释为1微米；物理单位误差只在可靠标定子集报告并给出分母。

## 工程边界与产物

后续拟新增共享的坐标预测适配与验证校准工具；输入为sample_id、原像素坐标、检测分数、有效尺寸和真值，输出公共格式。优先复用`deepblink_pytorch/deepblink_torch/evaluation.py`，不为不同方法各写一套匹配算法。现有CLI评估须显式传入锁定阈值，以避免默认p=0.5和旧扫描规则混入v2。

产物：`protocol_lock.json`、`data_manifest.csv`、`group_metadata.csv`、`annotation_qc.md`、`calibration_spec.json`、基线可运行性报告和最小接口测试。元数据中的未知生物学分组明确写unknown，不能用唯一文件名替代个体ID。

完成标准：两组相同坐标输入得到相同评价；y/x、微米/像素、原视野边界、空预测和重复点都有针对性检查；阈值从验证数据产生且测试不会触发重选；v1/v2结果分开存档。协议锁定后才能进入完整搜索。
